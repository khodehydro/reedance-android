# تست خروجی Studio با کلیدهای ثابت

مرجع: Windows Studio commit `d961964` از شاخهٔ `arena/abbcc310-reedance-desktop`. هدر `RDPACK1`، AES-GCM، قالب امضای manifest و شناسهٔ `enc-main` تغییر نکرده‌اند؛ تغییر اصلی انتخاب کلید و شناسهٔ امضای `sig-studio-embedded` است.

- Android Debug برای manifest معتبر با شناسهٔ جدید، از جفت کلید عمومی امضا و AES سازگار با Studio استفاده می‌کند. تنظیم دستی کلید، اثر انگشت یا رمز کاربر برای این مسیر لازم نیست. کلید خصوصی امضا به اندروید منتقل نشده است.
- مسیر دانلود قبلی، تأیید امضا، محدودیت HTTPS، کنترل نسخه، طول/هش، احراز GCM و اعتبارسنجی ZIP/رسانه برقرارند. برنامه فایل بسته یا صوت را در APK قرار نمی‌دهد. کلید Studio فقط در source set دیباگ است. مسیر Release این شناسهٔ امضا را حتی اگر در تنظیمات محلی درج شود، نمی‌پذیرد.
- Studio seed امضا را در کد منتشر کرده است، پس امضای این کلید هویت ناشر را در تولید اثبات نمی‌کند: هر دارندهٔ seed می‌تواند manifest امضا کند. این مسیر فقط برای QA است؛ انتشار نیازمند کلید خصوصی تازه و خارج از سورس و باینری عمومی Studio است. AES مشترکِ داخل اپ نیز DRM نیست.
- `Drop/main/gulum-2/latest.json` هنگام بررسی هنوز با `sig-studio-58bd40` امضا شده بود. با Studio جدید، یک **نسخهٔ محتوای بالاتر از ۵** صادر کن و ابتدا `.rdpack` تازه و سپس `latest.json` همان خروجی را در همان پوشه منتشر کن. با تغییر نام یا امضای مجدد manifest قدیمی، AES بسته عوض نمی‌شود؛ خروجی تازه لازم است.
- بعد از ساخت و نصب Debug جدید، دانلود و نصب تازه را روی دستگاه امتحان کن. برای QA از محتوای آزمایشی استفاده کن و APK دیباگ را به کاربران انتشار نده. قفل Release دست‌نخورده است.
