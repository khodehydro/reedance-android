# Android installer: desktop password architecture alignment

> **Legacy implementation note — do not use as the target architecture for new Windows work.** The password-based workflow described below is being superseded by [the no-password Windows ↔ Android handoff](WINDOWS_NO_PASSWORD_HANDOFF.md). Windows exports the shared v1 encrypted format; Reedance Android must decrypt it automatically with its app-provisioned key. No user file password, Profile setup, or password-derived key should be required.

Reviewed desktop branch `arena/132cfe2a-reedance-desktop` at commit
`0d1f612ceacda4105207cdcde3dcc9325efe5279` (2026-11-13).
Source of truth: `docs/CRYPTO.md`, `src/main/keys.ts`, `crypto/pack.ts`,
`exporter.ts`, `validation.ts`, and the vendored schemas.

This document supersedes the previous AES-key-in-APK provisioning instructions.

## What changed in Studio

- A single operator file password, generated by Studio and displayed in Settings.
- AES key = PBKDF2-HMAC-SHA256(NFKC(password).ECMAScriptTrim(), UTF8
  `reedance-pack-v1`, 200000 iterations, 32 bytes).
- New exports always use `enc-main`; the RDPACK1 header, nonce, header AAD,
  ciphertext and GCM tag layout have NOT changed.
- `latest.json` is still emitted and signed with Ed25519. A shared file password
  is not a substitute for publisher identity on an untrusted network.
- Desktop now accepts Turkish via an explicit in-memory schema extension. The
  desktop lesson schema is byte-identical to `contracts/v1/lesson.schema.json`.
  Android's existing bundled extension changes only language/locale/lexemeId
  definitions to add `tr`; no reference contract was silently rewritten.

## Android operator workflow (no APK secrets)

1. Re-export the song with the updated Studio. Keep its original
   `vNNNNNN-sha256.rdpack` filename.
2. Open Android **Profile → Studio packages → Set or change file password**.
   Enter the same password as Studio, including hyphens. Do NOT paste it into
   chat, Git, build variables, assets, WorkManager input, or logs.
3. Select **Choose and install rdpack**, then choose the exported local file.
   Android uses the system document picker and persists read permission so the
   WorkManager request can survive process death. No broad storage permission is
   requested. Local import requires no network or `pack_distribution.json`.
4. After successful installation, open the song in its language's song list.
   The actual songId comes only from the GCM-authenticated, schema-validated
   lesson. Matching preview metadata may be merged for display/artwork, not used
   to invent or authenticate a songId.

The field is masked and is not saved in Compose instance state. Android derives
on an IO dispatcher, then stores only the AES key wrapped with an Android
Keystore AES-GCM master key, with authenticated context binding. The plaintext
password is not persisted. App backup is already disabled. Hardware-backed
Keystore availability depends on the device; this is not an absolute DRM or
root-compromise guarantee. Forgetting/replacing the key does not remove already
installed lessons; re-importing an old-password export requires entering that
old password again. Reinstalling the app loses the stored wrapping key.

**Old `enc-studio-e896d1` exports (including the previously inspected Gülüm II
hash `e83715d2...aa092af`) do not become password-derived retroactively.** The
installer rejects legacy key IDs with an explicit re-export instruction; neither
a filename hash nor a new password can recover a random legacy AES key.

## Two explicit trust modes

### User-selected local file: `LOCAL_PASSWORD`

The operator explicitly chooses a file after a visible local-trust notice. It
must retain its exported filename; Android verifies its SHA-256 against that
filename, validates the header and password-based GCM tag before extracting,
then applies the SAME strict ZIP, schema, semantic, media and durable activation
checks as the network installer. A filename hash detects corruption, not authorship.
The filename version is not a signed freshness guarantee; local updates must
increase the installed version.

Local files **never** receive state `VERIFIED`, never update the signed
`SeenManifest` high-water mark, and cannot replace any song with a signed
publisher observation. Authentication by a shared password is not independent
publisher-signature verification. Existing local files remain readable offline.

### Network download: `VERIFIED`

Network installation still requires real HTTPS manifest URLs, host allowlisting,
and independently trusted raw32 Ed25519 public keys. Optional local build file:
`android/app/src/main/assets/pack_distribution.json` (gitignored), with:

- `allowedHosts`: explicit HTTPS host allowlist.
- `publicKeys`: signatureKeyId → canonical unpadded Base64URL raw32 public key.
- `songs`: actual songId → `{manifestUrl, language}`.
- `catalogBindings`: optionally `gulum-ii` → that real published songId.

There is **no `aesKeys` field required or consumed anymore**. Both modes use the
Keystore-wrapped password-derived `enc-main` key. Unknown signers remain errors;
network errors do not silently fall back to unsigned local trust. The app does
not invent a production host or learn a trusted signer from an untrusted file.

## Shared installation safeguards

WorkManager persists requests; interrupted transfers restart from zero. A
process-wide lock serializes installers and recovery. Data is staged in private
storage, streamed with size bounds, and never fully loaded/unzipped in memory.
The ZIP reader checks root allowlist, local/central consistency, CRC, size/ratio
bounds and exact deflate completion. Validation covers schema, IDs, timestamps,
references, tables, quiz permutations, cross-installed lexeme identity, media
hashes/magic, Android audio duration and image bounds. Alias migration remains
fail-closed. Activation fsyncs files/directories, renames on the same volume and
updates the Room pointer transactionally; pending markers allow crash recovery.
Old committed generations remain intact for in-use Media3 files. Local and
signed installed songs appear in Downloaded and share normal playback/learning.

## Evidence and remaining gates

- Node-generated PUBLIC TEST password vectors cover ASCII, NFKC/ECMAScript trim,
  Unicode UTF-8 and a complete enc-main AES-GCM container. Python independently
  verifies derivation/decryption and wrong-password rejection.
- New `PackPasswordTest` tests the same vectors and container in JVM code.
- Host suite:39 checks; transport inspector:8 checks. Kotlin syntax parsing is
  only a source check, NOT compilation.
- Native Gradle build/JVM tests could not execute here: Java/Android SDK absent.
  Run CI and device tests for Keystore, document permission persistence,
  cancellation, process death, low space, media decode and actual playback.
- The actual Gülüm II pack has NOT been decrypted/played: no new enc-main export
  and no operator password were supplied or requested in chat.
- No QR reader implemented (text entry is the supported path). Automatic old
  generation GC, progress-panel reattachment after recreation and full
  multi-song library/review navigation remain follow-ups.
- Network hosting and public-key provisioning remain publisher responsibilities.
  Production release audit and device verification are still required; the
  release Gradle guard remains closed.
